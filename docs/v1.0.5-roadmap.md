# Firefly v1.0.5 规划

v1.0.5 新增非 Spring Java 服务的 Firefly Remote Adapter，同时完整保留现有 Spring Boot Starter 行为。

## 范围

- Gateway 支持客户端声明“Executor 定义必须已存在”。
- `firefly-remote-adapter` 提供固定 Executor 注册、Handler 能力上报、配置加载和生命周期管理。
- `@FireflyHandler` 作为固定业务方法的主入口，自动使用 `包名.类名#方法名`。
- 只映射明确传入的对象，不做全局 classpath 扫描。
- 显式 `RemoteHandlerRegistry` 保留为低层兼容和动态适配 API。
- Adapter 配置沿用 `firefly.executor.*` / `FIREFLY_EXECUTOR_*` 命名。
- 发布 Maven Central 构件 `io.github.fishered:firefly-remote-adapter:1.0.5`。

## 非目标

- 不修改 `firefly-spring-boot-autoconfigure` 或 `firefly-spring-boot-starter`。
- 不允许 Adapter 创建或更新 Executor、Job、Cron 和其他调度定义。
- 不做全局 classpath 扫描。
- 不在 v1.0.5 实现 Python/Go SDK、通用 HTTP Handler 或语言无关 Agent。

## 分支栈

所有分支基于 `master@cec6368`，按以下顺序堆叠：

```text
master
└── future-executor-registration-policy-v1.0.5
    └── future-remote-adapter-core-v1.0.5
        └── future-remote-adapter-handler-mapping-v1.0.5
            └── fix-remote-adapter-config-v1.0.5
                └── doc-remote-adapter-v1.0.5
                    └── script-release-v1.0.5
```

每个功能分支保持实现与测试提交可独立评审；文档和版本发布配置不混入核心实现提交。

## 验收标准

- 已存在的 Executor 能注册实例并接收真实 Handler 调度。
- 未知 Executor 即使在 Gateway 全局允许自动创建时也会被拒绝，且控制面不产生新定义。
- 空或重复 Handler 集合在连接前失败。
- 注解方法签名错误在连接前失败。
- TLS、Integration Key、重连、幂等结果存储和优雅关闭可配置。
- Remote Adapter 测试、Javadoc、全仓测试和 Starter 兼容性测试通过。
- 相对 `master`，两个 Spring Starter 模块没有文件差异。

## 后续版本

语言无关 Agent 应作为单一开放式协议边界，负责连接 Gateway 并调用业务服务的本地 HTTP Handler。Python、Go 等语言如有需求，再提供只封装配置、协议与 Handler SDK 的薄包，避免在服务方暴露 Firefly 内部实现。

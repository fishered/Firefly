# Firefly 1.0.2 增量计划

1.0.2 聚焦生产安全、模块边界和故障恢复，不引入大型 Web 框架，也不改变 Netty 作为主要执行通信通道的定位。

## 增量范围

| 主题 | 目标 | 完成标准 |
| --- | --- | --- |
| Admin 请求边界 | 统一限制请求体、JSON、分页和批量操作 | 超限请求返回稳定错误；限制可配置并有测试 |
| Admin HTTP 拆分 | 从插件生命周期中分离路由、安全、审计和领域 Controller | `AdminHttpPlugin` 只负责装配与生命周期，现有 API 行为保持兼容 |
| Netty 边界 | 分离协议、Gateway 协调和 Executor Client | 依赖方向单向，协议兼容测试覆盖新旧版本 |
| 线程池背压 | 提供有限等待和可观测的重试拒绝策略 | 不阻塞 EventLoop；队列饱和、关闭和最终失败均有测试 |
| 调度类型一致性 | 禁止保存当前运行时不能执行的调度类型 | API、UI、持久化和运行时对能力认知一致 |
| 插件兼容 | 声明 Plugin API 与 Firefly 版本范围 | 不兼容插件在启动前给出明确诊断 |
| 数据库故障测试 | 覆盖连接抖动、锁竞争、主库切换后的恢复边界 | PostgreSQL/MySQL CI 可重复执行，结果不依赖固定 sleep |
| 在线 reshard | 提供受控的分片扩容流程 | 有集群互斥、epoch/fencing、迁移进度、恢复和回滚边界 |

## 非目标

- 不实现尚未定义语义的“失败注册表”。
- 不引入 Spring MVC、WebFlux、Quarkus HTTP 等大型 Web 运行时。
- 不允许无限等待、无限重试或在 Netty EventLoop 中阻塞。
- 在线 reshard 第一阶段只考虑扩容；缩容需要单独设计任务归属和容量校验。

## 实施顺序

1. Admin 安全边界与结构拆分。
2. 调度类型能力校验。
3. Netty 协议与 Gateway 拆分，同时落地线程池背压策略。
4. 插件兼容声明和数据库故障测试。
5. 基于持久化 epoch 的在线分片扩容。
6. 版本、迁移文档、发布检查和完整回归。

每个主题从最新 `master` 创建独立 `future-*` 分支，采用多段小提交并通过独立 PR 直接合入
`master`。全部 PR 合并且 `master` 完成回归后，再创建 `v1.0.2` tag 和 GitHub Release。
